01 — Getting started

Quick Start #

No jQuery. No build step. Drop two files and go.

  1. 1

    Include files

    HTML

    Script tag

    <!-- CSS -->
<link rel="stylesheet"
      href="/path/to/flexdatalist.css">

<!-- JS (no jQuery needed) -->
<script src="/path/to/flexdatalist.js"></script>

    npm

    // npm install flexdatalist
import Flexdatalist from 'flexdatalist';
import 'flexdatalist/css';
  2. 2

    HTML — auto-init

    Any input with an fdl-* attribute (or the class flexdatalist) is initialised automatically on DOMContentLoaded.

    index.html HTML 
    <input type="text"
       fdl-data="/api/items.json"
       fdl-search-in="name"
       fdl-min-length="1"
       name="item">
  3. 3

    JavaScript — programmatic init

    app.js JS 
    // init() is async — resolves after initial data loading is done
const [fd] = await Flexdatalist.init('#city', {
    url:            '/api/cities',
    searchIn:       ['name', 'zip'],
    valueProperty:  'id',
    textProperty:   '{name}, {zip}',
    minLength:      2,
});

// Chainable API
fd.setValue('42')
  .on('select:flexdatalist', e => console.log(e.detail));

// Get the stored value at any time
console.log(fd.getValue());

// When constructing directly, use .ready instead
const fd2 = new Flexdatalist(document.querySelector('#city'), opts);
await fd2.ready; // resolves once initial data is loaded

Auto-init: Inputs with an fdl-* attribute, or the class flexdatalist, are initialised automatically unless they carry the class autodiscover-disabled. Options are read from fdl-* attributes (camelCase → kebab-case). For HTML that passes a validator, write data-fdl-*; the v2 form data-* also still works.

CSS compatibility: The new standalone class uses the exact same CSS class names as the original jQuery plugin, so CSS overrides written for v2 keep working on top of flexdatalist.css.

02 — Data

Data Sources #

Three ways to provide data.

A

Static Array

Pass a JS array via the data option.

app.jsJS
Flexdatalist.init('#el', {
  data: [
    {id: 1, label: 'Apple'},
    {id: 2, label: 'Banana'},
  ]
});
B

Static JSON File

Point data to a URL — loaded once and cached.

index.htmlHTML
<input
  fdl-data="items.json"
  fdl-search-in="label"
  name="item">
C

Remote URL

recommended for large sets

Use url — queried on every keystroke.

index.htmlHTML
<input
  fdl-url="/api/search"
  fdl-search-in="name"
  name="item">

Server receives: keyword contain selected load relatives

Server response format #

Return a plain array [{...}] or wrap it:

response.jsonJSON
{
  "results": [ { "id": 1, "name": "Paris" }, ... ],
  "options": { "url": "/api/next-endpoint" }  // optional — override options from server
}

03 — Reference

Options #

Set via JS constructor object or fdl-* attributes (camelCase → kebab-case, e.g. fdl-min-length="2"; data-fdl-* and data-* also work). Options can also be changed at any time via fd.setOption(name, value). Options that name an item property also take a dotted path into nested objects, such as valueProperty: 'employee.number' or searchIn: ['name', 'office.city.name'].

04 — Reference

API #

All instance methods are chainable (return this) unless they return a value.

Static 3

Flexdatalist.init(selector, options) → Promise<Flexdatalist[]>

Initialise on one or many elements. Accepts a CSS selector string, HTMLElement, or NodeList. Resolves after all instances have finished loading their initial data.

Flexdatalist.getInstance(el) → Flexdatalist|null

Return the instance attached to a given element, or null.

instance.ready → Promise<Flexdatalist>

Promise that resolves with the instance once initial data loading is complete. Useful when constructing instances directly with new Flexdatalist(el, opts).

Options 2

fd.getOption(name) → any

Return the current value of an option.

fd.setOption(name, value) → this

Update an option at runtime. Chainable.

Value 7

fd.getValue() → string|Object|Array

Return the stored value as a string, parsed object, or array (multiple mode).

fd.getText(format?) → string|string[]

Return the user-facing display text shown in the alias input. Single mode always returns a string. Multiple mode: 'array' (default) returns a string[]; 'string' joins with the configured valuesSeparator; any other string is used as a custom join separator (e.g. ' | ').

fd.setValue(val) → this

Replace the current value. Triggers a data load to resolve display text.

fd.addValue(val) → this

Add a value in multiple mode.

fd.removeValue(val) → this

Remove a value in multiple mode.

fd.toggleValue(val) → this

Add the value if not present, remove if already present.

fd.clear() → this

Clear all values and reset the alias input.

State 5

fd.disable() → this

Disable the input.

fd.enable() → this

Enable the input.

fd.readonly(state?) → boolean|this

Called with no argument: returns current readonly state. Called with boolean: sets readonly state (chainable).

fd.isDisabled() → boolean

Return true if currently disabled.

fd.isReadonly() → boolean

Return true if currently readonly.

Search & Results 2

fd.search(keyword) → this

Programmatically trigger a search with the given keyword.

fd.closeResults() → this

Close the results dropdown.

Event Binding 2

fd.on(eventName, handler) → this

Attach an event listener on the underlying <input> element. Chainable.

fd.off(eventName, handler) → this

Remove a previously attached event listener. Chainable.

Lifecycle 1

fd.destroy(clear = false) → void

Remove all DOM additions, unbind all listeners, and unregister the instance. Pass true to also clear the original element's value.

Chaining example #

tags.jsJS
const [fd] = await Flexdatalist.init('#tags', {
    data:           myArray,
    multiple:       true,
    selectionRequired: true,
    limitOfValues:  5,
});

fd.setValue('1,2,3')           // pre-select three values
  .setOption('limitOfValues', 10) // change an option at runtime
  .on('change:flexdatalist', e => {
      console.log('changed', e.detail); // { value, text }
  })
  .on('select:flexdatalist', e => {
      console.log('selected item', e.detail); // the full item object
  });

// Later…
fd.addValue('4').disable();

// Or via native addEventListener
document.querySelector('#tags')
  .addEventListener('select:flexdatalist', e => console.log(e.detail));

05 — Reference

Events #

All events are dispatched as CustomEvent on the original <input> element. The payload is available at e.detail. Listen with fd.on(eventName, handler) or the native el.addEventListener(eventName, handler).

Type, pick, remove a tag — each CustomEvent is printed on the right. Search events fire after searchDelay (300 ms).

Events appear here as they fire.

    Event listener example #

    city.jsJS
    const el = document.querySelector('#city');

// Using the fd instance (chainable)
const [fd] = await Flexdatalist.init(el, { url: '/api/cities' });
fd.on('select:flexdatalist', e => {
    console.log('Selected:', e.detail);
    // e.detail → { id: 42, name: 'Paris', country: 'FR' }
});

// Or using native DOM event (dispatched on the <input> element)
el.addEventListener('change:flexdatalist', e => {
    console.log('Value changed:', e.detail.value, '→', e.detail.text);
});

    07 — Integration

    React, Vue & Svelte #

    No adapter package needed: a small component around the core is enough. Render the input inside a wrapper element, then on mount set the initial value, listen to change:flexdatalist and create the instance with new Flexdatalist(input, options); on unmount call destroy(). Full components are in the README.

    CityPicker.vue Vue

    Vue 3 — CityPicker.vue

    <script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue';
import Flexdatalist from 'flexdatalist';
import 'flexdatalist/css';

const props = defineProps({ modelValue: String });
const emit = defineEmits(['update:modelValue']);
const inputRef = ref(null);
let instance = null;
const onChange = (e) =>
  emit('update:modelValue', e.detail.value);

onMounted(() => {
  const input = inputRef.value;
  input.value = props.modelValue ?? '';
  input.addEventListener('change:flexdatalist', onChange);
  instance = new Flexdatalist(input, {
    url: '/api/cities', minLength: 2,
  });
});
onBeforeUnmount(() => instance?.destroy());
</script>

<template>
  <div><input ref="inputRef" /></div>
</template>

    React — CityPicker.jsx

    import { useEffect, useRef } from 'react';
import Flexdatalist from 'flexdatalist';
import 'flexdatalist/css';

function CityPicker({ onChange }) {
  const inputRef = useRef(null);
  const onChangeRef = useRef(onChange);
  onChangeRef.current = onChange;

  useEffect(() => {
    const input = inputRef.current;
    const handle = (e) =>
      onChangeRef.current?.(e.detail.value);
    input.addEventListener('change:flexdatalist', handle);
    const instance = new Flexdatalist(input, {
      url: '/api/cities', minLength: 2,
    });
    return () => {
      input.removeEventListener('change:flexdatalist', handle);
      instance.destroy();
    };
  }, []);

  return <div><input ref={inputRef} /></div>;
}

    Svelte — CityPicker.svelte

    <script>
  import { onMount } from 'svelte';
  import Flexdatalist from 'flexdatalist';
  import 'flexdatalist/css';

  export let value = '';
  let input;

  onMount(() => {
    input.value = value;
    const handle = (e) => { value = e.detail.value; };
    input.addEventListener('change:flexdatalist', handle);
    const instance = new Flexdatalist(input, {
      url: '/api/cities', minLength: 2,
    });
    return () => {
      input.removeEventListener('change:flexdatalist', handle);
      instance.destroy();
    };
  });
</script>

<div><input bind:this={input} /></div>

    Why a wrapper element?

    Flexdatalist adds its own elements next to the input; a <div> that only this component uses keeps them out of the framework's way.

    Why new and not await init()?

    Creating the instance synchronously means unmounting early (or React StrictMode's double mount) can always destroy it.

    Changing the value later

    keep the instance and call instance.setValue(value).

    Deprecated. The flexdatalist-vue, flexdatalist-react and flexdatalist-svelte packages are deprecated.

    08 — Upgrading

    Migrating from jQuery Plugin #

    Key differences when upgrading from the original jquery.flexdatalist.js.

    − Before (jQuery)JS
    $('#el').flexdatalist({ url: '/api' });

$('#el').flexdatalist('value');
$('#el').flexdatalist('value', '42');
$('#el').flexdatalist('add', 'val');
$('#el').flexdatalist('remove', 'val');
$('#el').flexdatalist('disabled', true);
$('#el').flexdatalist('destroy');

$('#el').on('change:flexdatalist',
    function(evt, set, opts) {
        console.log(set.value, set.text);
    });
    + After (ES6 Class)JS
    const [fd] = await Flexdatalist.init('#el', { url: '/api' });

fd.getValue();
fd.getText();                    // ['Paris', 'London']
fd.getText('string');            // 'Paris,London'
fd.getText(' | ');               // 'Paris | London'
fd.setValue('42');
fd.addValue('val');
fd.removeValue('val');
fd.disable();
fd.destroy();

fd.on('change:flexdatalist', e => {
    console.log(e.detail.value, e.detail.text);
});
// or: el.addEventListener('change:flexdatalist', e => ...)

    What changed #

    • CSS: Same class names, so your overrides keep working. Swap jquery.flexdatalist.css for flexdatalist.css to get the v3 look and the --fdl-* theme variables. Running v2 and v3 side by side? Set classPrefix, e.g. 'fd3-'.

    • HTML data-* attributes: Still work, so existing markup needs no changes. New markup can use the shorter fdl-* form (e.g. fdl-url), which never clashes with other scripts' data-* attributes.

    • Events: Same event names. Payload moved from jQuery extra args to e.detail (CustomEvent).

    • Alias input: No longer given a name attribute — never double-submitted.
